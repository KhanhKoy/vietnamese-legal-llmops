- Cần chuẩn hóa text trước khi chia: bỏ `\r\n`, gộp khoảng trắng, giảm dòng trống thừa.
- Mục tiêu của chunking là giúp truy xuất chính xác hơn khi làm RAG cho dữ liệu pháp luật.

15) Cập nhật mới về xử lý tràn RAM:
- `src/rag_core/dataset_reader.py`
  - đọc metadata bằng streaming
  - đọc `content.parquet` theo batch nhỏ bằng `iter_batches()`
  - không dùng `pandas` cho toàn bộ row group lớn nữa
- `src/rag_core/pipeline.py`
  - xử lý theo luồng: document -> chunk -> embed -> add vào vector store
  - gom chunk theo batch nhỏ trước khi embed
  - tránh giữ toàn bộ document/chunk trong RAM cùng lúc
- `src/rag_core/vector_store.py`
  - lưu vector store xuống SQLite thay vì giữ toàn bộ embeddings trong RAM
  - đọc/chấm điểm theo từng batch khi search
  - giảm nguy cơ tràn RAM khi corpus lớn

18) Cập nhật tối ưu RAM khi build index:
- `src/rag_core/dataset_reader.py`
  - đã thay cách giữ toàn bộ metadata trong RAM
  - metadata được stream vào SQLite tạm trên ổ đĩa
  - content vẫn đọc theo `iter_batches(batch_size=64)`
  - lookup metadata bằng SQLite thay vì Python dict lớn
  - giảm nguy cơ OOM khi metadata rất lớn

- `src/rag_core/vector_store.py`
  - thêm `commit()` để commit SQLite định kỳ
  - giảm tích tụ WAL cache khi `add()` liên tục
  - hỗ trợ pipeline flush/commit theo lô

- `src/rag_core/pipeline.py`
  - thêm `gc.collect()` sau mỗi lần commit định kỳ
  - commit sau mỗi `commit_interval` chunk
  - giảm bộ nhớ tạm của chunk dicts, embeddings buffer, document strings
  - build index theo luồng streaming, không giữ toàn bộ dữ liệu trong RAM

19) 3 vấn đề tràn RAM đã được xử lý:
- metadata lớn không còn load vào Python heap
- WAL cache SQLite được commit định kỳ
- đối tượng tạm được thu hồi bằng garbage collection

src/rag_core/dataset_reader.py

Thêm hỗ trợ đọc tài liệu từ S3 khi biến môi trường USE_S3 được bật.
Giữ lại chế độ đọc từ dataset Hugging Face (snapshot) khi chạy local.
Mỗi đối tượng S3 (tệp .txt hoặc .pdf) được xử lý dưới dạng một documento.
src/rag_core/chunking.py

Cải tiến hàm split_text để ưu tiên cắt tại các heading pháp lý (Chương, Điều, Mục, Khoản) và giữ chúng bên trong chunk.
Nếu chunk vượt quá kíchくん cho phép, sẽ sử dụng sliding‑window bên trong đó.
src/rag_core/embeddings.py

Thêm tính năng sử dụng Amazon Bedrock Titan Embedding qua biến môi trường USE_BEDROCK_EMBEDDING.
Khi không sử dụng Bedrock, fallback về Sentence‑Transformer local (sentence‑transformers/paraphrase‑multilingual‑MiniLM‑L12‑v2).
Đảm bảo vector được chuẩn hoá L2 để tương thích với tìm kiếm cosine similarity.
src/rag_core/vector_store.py

Thay đổi khỏi FAISS + SQLite sang PostgreSQL + extension pgvector.
Tự động tạo extension và bảng chunks với cột vector.
Tạo chỉ mục ivfflat để tìm kiếm gần đúng nhanh (cosine similarity).
Cung cấp các phương thức reset, add, search_by_embedding, search tương thích với API cũ.
src/rag_core/config.py

Thêm cấu hình kết nối PostgreSQL: pg_database, pg_user, pg_password, pg_host, pg_port (đọc từ biến môi trường).
requirements.txt

Thêm gói psycopg2-binary để kết nối PostgreSQL.
src/rag_core/lambda_handler.py (mới)

Hàm Lambda được kích hoạt bởi sự kiện S3 ObjectCreated.
Tải file từ S3 (hỗ trợ .txt và .pdf), trích xuất văn bản, thực hiện chunking, tạo embedding (qua EmbeddingService – có thể là Bedrock hoặc local), rồi lưu vào PostgreSQL qua VectorStore.
Đóng kết nối sau mỗi batch.
Các bước tiếp triển khai
Cấu hình môi trường:

Đặt USE_S3=true và cung cấp VECTOR_S3_BUCKET (tùy chọn VECTOR_S3_PREFIX) nếu muốn đọc từ S3.
Đặt USE_BEDROCK_EMBEDDING=true và cấu hình AWS credentials (hoặc dùng IAM role) để sử dụng Bedrock Titan Embedding.
Cung cấp thông tin kết nối PostgreSQL qua các biến PGDATABASE, PGUSER, PGPASSWORD, PGHOST, PGPORT (hoặc dùng giá trị mặc định trong Settings).
Đảm bảo extension pgvector đã được cài đặt trên instance PostgreSQL/RDS.
Triển khai Local:

Để phát triển và kiểm thử nhanh, giữ USE_S3=false và USE_BEDROCK_EMBEDDING=false.
Chạy python scripts/build_index.py để tạo vector store local (sử dụng PostgreSQL local nếu đã cấu hình, hoặc dựa vào VECTOR_STORE_DIR để sử dụng SQLite/FAISS cũ nếu chưa cài PostgreSQL – nhưng lưu ý rằng vector_store.py hiện tại chỉ hoạt động với PostgreSQL; cần giữ bản sao cũ nếu muốn dùng SQLite).
Triển khai AWS:

Đóng gói lambda_handler.py cùng với các module phụ thuộc (chunking.py, embeddings.py, vector_store.py, config.py) vào một deployment package (có thể dùng Docker hoặc AWS SAM/ CDK).
Tạo hàm Lambda, cấu hình trigger từ bucket S3, và cấp<IAM> role cho phép truy cập S3, Bedrock, và RDS.
Khởi tạo một instance Amazon RDS PostgreSQL với extension pgvector và tạo database/user dựa trên env var.
(Tùy chọn) Đặt lên VPC với private subnet để Lambda có thể truy cập RDS mà không cần public internet; dùng VPC Endpoint cho Bedrock và S3 nếu cần.
Kiểm thử:

Upload một file văn bản法律 (txt hoặc pdf) vào bucket S3 (hoặc dùng local minstack/mock).
Xác認 Lambda được kích hoạt, thực hiện chunking, gọi embedding (local hoặc Bedrock), và lưu vào PostgreSQL.
Truy vấn bằng VectorStore().search("câu hỏi của bạn") để nhận được các chunk liên quan.
